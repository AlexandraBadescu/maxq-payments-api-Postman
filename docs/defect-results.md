Generated by `npm run test:defects`. Each row is a full run of the suite against the service with one deliberate bug switched on.

**14 of 14 caught by the scenario meant to catch them.** The suite also passed with no bug switched on.

| Requests with no token are accepted | Yes | 15 |
| One customer can read and act on another customer's payment | Yes | 16 |
| A declined payment can be captured | Yes | 13 |
| An order can be paid for twice | Yes | 14 |

| A capture with no notification stays pending for ever | Yes | 11, 12 |
| A late success after a timeout is thrown away | Yes | 12 |
| A repeated notification moves the money a second time | Yes | 07, 08 |
| A failure notification can reverse a settled capture | Yes | 09 |
| A refund can exceed the captured balance | Yes | 03 |
| A refund can be requested before capture | Yes | 03, 04, 11 |
| A partial refund is recorded as a full refund | Yes | 01, 02, 08 |

These are bugs I chose, so this shows the suite catches these failures. It does not show that the suite would catch every possible bug.
